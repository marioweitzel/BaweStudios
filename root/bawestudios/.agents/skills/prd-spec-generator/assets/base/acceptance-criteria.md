# ACCEPTANCE CRITERIA STANDARD

Version: 1.0

## PURPOSE

Acceptance Criteria define when a feature is considered complete.

Nothing else.

---

# FORMAT

Preferred:

Given

When

Then

---

Alternative:

Condition

Action

Expected Result

---

# REQUIREMENTS

Criteria must be:

Objective

Measurable

Binary

Repeatable

Automatable

---

# NEVER USE

Easy

Fast

Beautiful

Modern

Friendly

Simple

Useful

Professional

These are opinions.

Not criteria.

---

# EXAMPLES

GOOD

Given

User is authenticated.

When

User saves profile.

Then

Changes are stored successfully.

---

BAD

Profile works correctly.

---

# ERROR SCENARIOS

Every important feature should define:

Invalid input

Permission denied

Network error

Unexpected state

---

# AUTOMATION

Every criterion should be reusable later by:

Testing Gate

QA

E2E Tests

API Contract Tests

Cross Validation

---

# CHECKLIST

□ Observable

□ Testable

□ Binary

□ Independent

□ Non ambiguous

□ Covers success

□ Covers failure
