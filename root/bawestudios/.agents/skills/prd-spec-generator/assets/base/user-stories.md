# USER STORIES STANDARD

Version: 1.0

## PURPOSE

Every feature inside the PRD must be represented as one or more User Stories.

User Stories represent user value.

Never implementation.

---

# FORMAT

As a

[user]

I want

[action]

So that

[benefit]

---

# REQUIRED FIELDS

ID

Priority

Actor

Story

Business Value

Dependencies

Acceptance Criteria

---

# PRIORITY

HIGH

Essential for product delivery.

MEDIUM

Important.

Can wait.

LOW

Future improvement.

---

# STORY RULES

Each story must:

Represent only one goal.

Represent only one actor.

Represent one business value.

Never combine multiple features.

---

# BUSINESS VALUE

Always explain why this feature exists.

Avoid:

"because yes"

"modern"

"nice"

"cool"

---

# DEPENDENCIES

Only mention dependencies when absolutely required.

Avoid dependency chains.

---

# ANTI PATTERNS

Bad:

Register, login and recover password.

Good:

Register

Login

Recover password

Three independent stories.

---

# ESTIMATION

Do not estimate time.

Do not estimate complexity.

Those belong to planning.

---

# CHECKLIST

Every story:

□ Has one actor

□ Has one action

□ Has one benefit

□ Has acceptance criteria

□ Belongs to product delivery or Deferred Scope

□ Is independent
